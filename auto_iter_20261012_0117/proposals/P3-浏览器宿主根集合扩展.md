# 提案 P3：浏览器宿主根集合扩展（OffscreenCanvas / Worker / indexedDB 等平台全局）

- **来源**：项目记忆"尚未实现"清单原文："浏览器宿主根集合只有 7 项，明显窄于 Node 侧；`OffscreenCanvas`、`Worker`、`indexedDB` 这类平台全局不会把浏览器运行时拉进候选集。"

## 三问论证

1. **机理审视**：宿主根表（HOST_GLOBAL_ROOTS / HOST_RUNTIME_ROOTS）决定"这个全局属于哪个宿主"，进而影响 required→target 候选集扩展。缺一个浏览器平台根，意味着依赖它的代码不会把浏览器拉进候选集，可能停在 UNKNOWN（保守但不精确）。注意第十五轮教训：**归属必须成立**——只加"平台规范定义 + 实测仅浏览器存在"的根，绝不加应用自带全局。
2. **前后对比**：改动前：依赖 `OffscreenCanvas` 等的折叠点无法借 required 扩展把浏览器纳入候选；改动后：这些点可以进入正确的候选集。**必须验证**：主基准五份数字是否变化、实测不实折叠是否仍为 0；若放行率异常上升而差分证据不支撑，立即回退。
3. **价值论证**：中风险、中收益：方向是提高判定精度而非放行率；但历史上同类改动（§7.6）曾有"映射改动无副作用"的先例（setImmediate/clearImmediate/MutationObserver 三个漏映射修掉后五份主基准数字完全未变）。值得先测量再决定。

## 实施前置（硬性门槛，缺一不实施）

1. 跑 `npm run eval:host-attribution`，拿到当前候选清单与"仅单一宿主存在"的实测证据；
2. 每个候选根找到规范依据（WHATWG HTML / DOM 标准），排除应用自带全局；
3. 若实测显示候选在 Node/微信也有存在（跨宿主全局，如 fetch/Blob/crypto），**不加**（§7.6 既定结论）；
4. 改后重跑受影响基准，确认 0 不安全折叠与危险方向迁移为 0；主基准数字若有变化，按项目惯例记录为口径变化而非"纠正"。
5. 若任何一条不满足：只更新本提案的"测量结果"小节，不动代码，留待用户审核。

## 测量结果（2026-10-12 周期 3，基于既有产物 `datasets/host-attribution/host-attribution.json`，generatedAt 2026-09-23）

既有产物 356 根、17 个"仅单一宿主存在且未映射"候选，分类如下：

**微信侧 10 个——全部不加（第十五轮已证伪归属）**

| 候选 | 结论 |
|---|---|
| `wh`/`$gwx`/`$gwn`/`$gwl`/`gra`/`grb` | wcc 编译产物在**文件内自赋值**的隐式全局（1496/1496 文件内有赋值），不是宿主能力 |
| `define`/`requireOnce`/`f` | 应用/编译器自带全局，非平台能力 |
| `__wxConfig` | 基础库私有全局，第十五轮实测：强归属会与"逐项目实例化子路径"混淆，曾造成 295 条错误放行，保持 UNKNOWN 是正确的 |

**Edge 侧 7 个——实测仅 Edge 存在（语言基线/Node/微信均无），全部为平台能力**

| 候选 | 规范归属 |
|---|---|
| `FileReader` | W3C File API（暴露于 Window/Worker 全局） |
| `Image` | WHATWG HTML，`HTMLImageElement` 构造器（Window 全局暴露） |
| `SVGRect` | W3C SVG2 几何接口（Window 全局暴露） |
| `Window` | WHATWG HTML `Window` 接口构造器 |
| `close` / `stop` | WHATWG HTML `window.close()` / `window.stop()` 方法（全局属性） |
| `WebKitCSSMatrix` | CSSOM 兼容性标准（legacy，非核心规范）——**可选**，建议单独决定 |

（规范归属为 API 的标准通名；具体章节锚点未逐条核验，实施前可再对锚点。）

**建议实施集合**：6 个核心规范 API（`FileReader`、`Image`、`SVGRect`、`Window`、`close`、`stop`）加入 `HOST_RUNTIME_ROOTS` 的 Edge 组（与 §7.6 `setImmediate`/`MutationObserver` 同位置，`contract-builder.mjs` 导出）；`WebKitCSSMatrix` 由用户单独决定。

**预期效果方向**：依赖这些根的未解析全局从 UNKNOWN 转为有证据判定（required=browser → 候选集扩展；vm 基线"不存在" vs Edge"存在" → PROTECT）。主要是 UNKNOWN→PROTECT 的**精度**收益，不应产生新 FOLD（§7.17 规则已堵住"基线不存在 → language-only 放行"的路径）。风险方向：若浏览器语料有应用级同名全局（跨 script 泄漏），会被过度归因为浏览器（方向保守，BLOCK_FOLD），可接受但要观测过度保护数。
