# 提案 P1：混淆不变性基准扩展为链式变换（M1/M2 → M3/M4 链式组合）

- **来源**：JsDeObsBench（CCS 2025，DOI 10.1145/3719027.3744871）的威胁模型——用 javascript-obfuscator 链式组合至多 7 种变换生成评测样本。
- **动机**：第三十二轮 obfuscation-invariance 只有 M1（字符串数组化）与 M2（+控制流平坦化 0.7+死代码 0.3）两档。审稿人可能质疑"混淆档位太少、不代表真实威胁"。

## 三问论证

1. **机理审视**：R97 的混淆不变性主张是"混淆不改变实体的环境差分物理事实，R97 保持 0 不安全折叠"。链式变换是该主张更强的压力测试：更多别名断裂、更多字符串编码、更多控制流重组，BINDING_UNRESOLVED 应进一步上升（安全方向），不安全折叠必须仍为 0。机理与现有主张完全一致，只是压力更大。**不触碰 required/target 分离与 dropAbsence 铁律。**
2. **前后对比**：改动前：2 档 × 112 文件；改动后：新增 M3（M2+字符串数组旋转/洗牌）、M4（M3+自我防卫 debugProtection+自爆炸）等 2 档。预期：一致性下降（更多 FOLD→UNKNOWN）、0 不安全折叠保持。若出现**任何**不安全折叠，即为重要发现——按第三十二轮协议现场从证据读数推导差分实体并归因，绝不掩盖。
3. **价值论证**：评测-only 改动，不进决策链路；直接回应审稿风险；与 CCS 2025 威胁模型对齐有引用背书。值得做。

## 实施要点（供周期 2–4 执行）

- 位置：`src/evaluation/obfuscation-invariance.mjs` 的配置表；新增 `M3`/`M4` 配置项，复用 worker_threads + 60s 超时机制。
- 注意 `renameGlobals: false` 必须保持（实体跨版本配对前提）；`debugProtection` 可能导致探针卡死——先小样本（3 文件）试跑确认可行性，不可行则降级为"字符串数组+编码+控制流"组合并在报告注明。
- 验证：`npm test` 全绿 + 重跑 `npm run eval:obfuscation-invariance` + 0 不安全折叠 + 危险方向迁移为 0；结果更新到性能指标数据报告（与 P2 联动）。
- 提交：`auto-iter<N>: 混淆不变性扩展链式变换 M3/M4`。
