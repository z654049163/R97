## 2. 工作循环（每个自动化周期执行一轮）

1. **LOCK 检查**：若本文件夹下 `LOCK` 存在且修改时间在 50 分钟内，说明上一周期仍在运行，本次直接结束。否则创建 `LOCK`（写入周期号与开始时间）。
2. **状态恢复**：读本文件与 `PROGRESS.md` 末尾（最新 2–3 个周期记录），确定本次周期主题（见 §4 周期表）。
3. **文献检索**：用 WebSearch/WebFetch 检索，顶会顶刊优先（ICSE / FSE / ASE / ISSTA / USENIX Security / CCS / NDSS / S&P / IMC / TSE / TOPLAS / TDSC）。每篇写入 `literature/<短名>.md`，模板见 §5。
4. **批判性过滤**（三问，全部通过才允许进入实施）：
   - ① 机理审视：该技术在 R97 语境下的真实机理是什么？与"required / target 严格分离""目标只认外部证据""纯语言内建 vs 宿主能力"正交边界是否兼容？
   - ② 前后对比：改动前后效果如何？是否有实测数据支撑变好？会不会破坏既有 0 不安全折叠红线、`dropAbsence` 铁律、非对称外推铁律？
   - ③ 价值论证：是否值得、是否适合当前阶段？有没有真实语料正向收益？还是未经消融验证的过度设计？
5. **实施**：小步、外科手术式改动，只改与目标直接相关的行。改完必须 `npm test`（串行，约需数分钟）**全部通过**才保留；测试不过则回退本次改动（`git checkout -- <文件>` 或 `git restore`）并在 PROGRESS.md 记录失败原因。
6. **提交**：每个完成且通过测试的改动，`git add <相关文件>` + 本地提交，消息格式 `auto-iter<N>: <一句话描述>`。**绝不 push。**一次提交只含一个逻辑改动。
7. **文献库维护**：新论文按标准格式追加到 `R97_已读文献库与技术借鉴全景录.md`。**铁律：新增条目必须当场过 CrossRef / arXiv / 官网核验（作者全名、venue、年份、DOI 三件套）；核实不到的字段显式标注 `UNVERIFIED`，绝不凭记忆填引用。**
8. **收尾**：更新 `PROGRESS.md`（周期号、时间、做了什么、产出文件、测试结果、下一步建议），删除 `LOCK`。

## 3. 项目红线（来自 AGENTS.md 与项目记忆，逐条有效）

- required runtime（依赖什么宿主能力）与 target runtime（实际部署环境）严格分离；target 只能来自被分析代码之外的外部证据。
- 只有 `confirmed target + definite required + 真实冲突` 才硬 PROTECT；`declared`、`inferred`、`experiment_config` 不能授权 FOLD 也不能单独触发硬 PROTECT。
- 纯 JavaScript、局部变量、被遮蔽的宿主 API 不加入 required；稳定别名可继承宿主属性。
- **非对称外推铁律**："存在"可以外推，"不存在"绝对不能外推；`dropAbsence` 防线不可逾越。
- v1 禁区：大型 API 语义知识库、完整数据流分析/过程间分析、ML/LLM 直接决定折叠、微信全量子环境自动执行。
- 新增组件必须直接改善：错误折叠防护、正常折叠保留率或真实微信证据覆盖，否则只进未来工作。
- 严禁为刷低未决率做"掩耳盗铃式过滤"或伪造存在性。
